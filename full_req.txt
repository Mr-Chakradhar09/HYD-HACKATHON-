Business Rules
One inventory record exists for each Product + Warehouse combination.
Product must exist and be ACTIVE.
Warehouse must exist and be ACTIVE.
Inventory quantities can never become negative.
Available Quantity is always calculated, never manually entered.
Inventory cannot exist without a Product.
Inventory cannot exist without a Warehouse.
Only the Movement Service is allowed to change Current Quantity through Kafka events.
Direct quantity updates through REST are prohibited.
Reservations reduce Available Quantity but do not change Current Quantity.
Damaged stock remains part of Current Quantity until disposed of through a movement.
Inventory adjustments require a mandatory reason.
Inventory records are never physically deleted.
All updates use optimistic locking.
Inventory Creation Validation
Before an inventory record is created:
JWT must be valid.
User must have permission.
Product must exist.
Product must be ACTIVE.
Warehouse must exist.
Warehouse must be ACTIVE.
Inventory for the Product + Warehouse combination must not already exist.
Initial quantity must be zero.
Status is automatically set to ACTIVE.

Inventory Update Validation
Inventory quantities cannot be modified directly through REST APIs.
Every inventory update must originate from the Movement Service through Kafka.
Before applying an update:
Movement Event must be valid.
Inventory record must exist.
Inventory status must be ACTIVE.
Product must still exist.
Warehouse must still exist.
Quantity after update cannot become negative.
Optimistic locking validation must succeed.

Reservation Validation
Before creating a reservation:
JWT must be valid.
User must have permission.
Inventory must exist.
Inventory must be ACTIVE.
Reservation quantity must be greater than zero.
Available quantity must be sufficient.
Reference number must be unique for the reference type.
Duplicate active reservation is not allowed.

Reservation Release Validation
Before releasing reserved inventory:
Reservation must exist.
Reservation status must be ACTIVE.
Release quantity must not exceed reserved quantity.
Inventory must exist.
Inventory must be ACTIVE.

Inventory Adjustment Validation
Before performing an adjustment:
JWT must be valid.
User must have permission.
Inventory must exist.
Inventory must be ACTIVE.
Adjustment type must be valid.
Quantity must be greater than zero.
Reason is mandatory.
Remarks are optional.
Quantity after adjustment must never become negative.
